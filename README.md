enseñan una vez. De la base de datos a la interfaz: si hace falta pensar el
modelo, montar el servidor y además dejarlo bonito, mejor.

Aprendí a programar haciendo, y sigo igual: cuando quiero entender algo de
verdad, me construyo algo con ello.

## En lo que ando

**[adrianosuna.com](https://github.com/adrianosuna/adrian-osuna-portfolio)** —
mi web, y detrás un panel de gestión que uso de verdad: mis finanzas con topes
por categoría y recibos que se apuntan solos, un tablero de oportunidades, las
cosas que caducan con su calendario, el estado de mi servidor y una API para
apuntar gastos desde un atajo del iPhone. Next.js, TypeScript, Prisma y MySQL,
en mi propio VPS con Docker.

Lo tengo público entero, capturas incluidas: si te sirve algo de ahí, cógelo.

## Cómo me gusta hacer las cosas

- **Entender el problema antes de escribir código.** Lo que no se ha visto de
  cerca se diseña mal.
- **El modelo de datos primero.** Uno claro hace la pantalla sencilla; al revés,
  cada pantalla nueva descubre un agujero.
- **Pensar en producción desde el principio:** los errores, las migraciones y
  quien lo mantenga dentro de dos años (que probablemente sea yo).
- **Escribir el porqué**, no solo el qué. Lo que no está documentado se olvida.
